# 官方服务套餐与平台整合交付设计方案

> 状态：已实施（2026-11-10）。本文件汇总三轮已确认口径与平台整合交付商业模式，并附方案评估与风险；落地与验收结果见 §十一。

## 一、背景与目标

平台官方按业务板块上架「服务套餐」，企业用积分采购；套餐由**平台整合多家优质服务商**完成交付——企业采购后，平台主持企业与多家服务商的签约来兑现套餐内容。

覆盖板块（板块级 `SERVICE_TYPES`，见 `backend/src/common/constants.ts`）：
营销服务 `MARKETING`、供销网络 `SUPPLY_NETWORK`、跨境出海 `EXPORT_REFUND`、灵活用工 `FLEX_WORK`、物流服务 `LOGISTICS`、IT服务 `SMART_SERVICE`、知识产权 `IP_SERVICE`、法律服务 `LEGAL_SERVICE`、智库服务 `THINK_TANK_SERVICE`、资产交易 `ASSET_TRADE`；财税 `TAX_FINANCE` 复用现有「财税服务包 · 参考价格」板块。

## 二、已确认口径

### 第一轮（基础形态）
1. 后台**独立板块「服务套餐」**（`ADMIN_SECTIONS`，归入 `billing` 组，紧邻「积分与充值」）。
2. 积分兑换价**按后台官方汇率实时换算**（`PointsSettingsService.view().rate`，默认 1 元=10 积分），购买时快照。
3. **所有板块**套餐均可积分直购。
4. 套餐**板块级**归属（一个套餐属于一个板块）。

### 第二轮（商业模式）
5. 套餐＝平台整合优质服务商的一揽子交付；卡片/详情统一声明「**本套餐由平台整合优质服务商完成交付**」。
6. 企业采购后由平台主持企业与多家服务商签约兑现；交付状态机见 §六。

### 第三轮（交付闭环细化）
7. **复用现有签约流程**：平台发起 → 服务商确认生效。**预设服务商同样只自动发起，不自动确认**；任何签约都必须等待服务商在「签约管理」确认后才生效。服务商**否决**或**迟迟不确认**时，平台可**更换发起签约主体**，**原 Offer 撤销**（原签约置 TERMINATED）。
8. **两种发起方式并存**：人工主持发起；或在套餐里**预绑优质服务商 + 开启「购买后自动发起」**，用户购买后自动发起签约。该开关做进套餐配置。
9. 套餐可配置**多个交付项、多家服务商**。
10. 企业侧「**我的套餐**」为**独立菜单**（非积分中心页签）。

### 第四轮（退款与口径校正）
11. **限购按企业**：额度按采购企业档案计数，同一企业的不同账号共享，不按账号各算一份。
12. **退款支持部分退与整单退**：部分退只回补积分、订单与交付保留；整单退退回剩余全部并关闭订单（须无已生效签约，撤销全部待确认签约）。
13. **套餐不参与交付周期与到期管理**：`unit`（年/月/次）仅用于价格展示，不生成周期、不做到期停服/续费提醒。
14. **展示口径**：内部状态键仍是 `DELIVERED`（避免迁移），界面统一显示为「**已签约**」，含义是全部交付项签约生效，而非服务履约完成。

### `Contract` 增补
- `packageOrderId Int @default(0)`（0=普通签约）：把平台主持的签约挂回订单，交付进度可反查、签约台账可溯源。

## 四、积分定价口径
- 人民币价 = `priceCents/100`；积分价 = `centsToPoints(priceCents, rate)`（复用 `recharge.service.ts` 同源公式，4 位小数）。
- 列表接口返回当前 `rate` 与算好的 `pointsPrice`，汇率调整即时反映。
- **购买所见即所扣**：购买确认弹窗实时取一次 quote（当前 rate 算积分价）再扣；订单快照 `rateAmount`/`pointsAmount`，永不追溯。

## 五、后端

### `ServicePackageService`
- 管理端：`adminList/adminSave/adminRemove/adminToggle`。
- 用户端：`publicList(serviceType)`（仅 ACTIVE，带 pointsPrice/rate/交付项预览）、`quote(packageId)`、`purchase(userId, packageId)`、`myOrders(userId)`。
- `purchase`：校验 ACTIVE + **按企业限购**（`enterpriseId` 计数，跨账号共享）+ 企业档案（个人主体按现有规则拦财税/出海交付项）→ `PointsService.debit(userId,'SPEND',points,{scene:'service_package',refType:'service_package',refId:orderNo})` → 落订单 PAID + 按 `deliveryItems` 生成明细（带预绑服务商）→ 计算 `fulfillmentStatus`。
- `quote` 与 `publicList` 的限购/已购标记同样按当前采购企业口径，保证同一企业多账号看到一致的剩余额度。
- **自动发起**（`autoInitiate=true` 且明细已预绑）：购买后 best-effort 调用平台主持签约；**只生成 PENDING，绝不代服务商确认**，服务商确认后才生效；**失败明细回落「待匹配」进交付队列，不阻断购买**（购买已扣分，交付转人工兜底）。

### 平台主持签约（复用现有签约）
- 新增 `ContractsService.initiateByPlatform(operator, { enterpriseId, providerUserId, serviceType, packageOrderId, agentId? })`：要求 `PLATFORM_ADMIN`，**抽出并复用** `create` 的备案/独占/重复/个人主体校验（公共私有方法，避免复制漂移），以订单企业为主体建 `PENDING` 签约并写 `packageOrderId`。服务商沿用现有 `confirm` 生效。
- **更换主体 / 原 Offer 撤销**：`replaceProvider(orderItemId, newProviderUserId)` → 若旧 `contractId` 为 PENDING/ACTIVE 先 `terminate`（原 Offer 撤销，置 TERMINATED，note 标注「平台撤回/服务商否决」）→ 以新服务商 `initiateByPlatform` 建新 PENDING → 回填明细 `contractId/providerUserId`。独占类目以 PENDING/ACTIVE 判占用，TERMINATED 不占用，故可换。
- 服务商否决：服务商对 PENDING 签约 `terminate`（现有 `isParty` 含服务商）→ 明细读 Contract.status=TERMINATED → 交付队列标「服务商已否决，待更换」。

### `ServicePackageFulfillmentService`
- `adminOrders`（队列，按企业/套餐/交付状态筛选，PENDING 时长排序标红）、`assignProvider(orderItemId, providerUserId)`（候选复用 `contracts.providerDirectory`/`candidates`）、`initiateSigning(orderId)`（批量主持发起）、`replaceProvider(...)`、进度汇总（全部明细 ACTIVE → DELIVERED，展示为「已签约」）。
- **退款（部分退 / 整单退）**：`refund(orderId, { amount?, remark? })`：
  - `amount` 省略 = 退回剩余全部（整单退）；`amount < 剩余可退` = 部分退，订单保持开放，交付与签约不受影响；
  - 整单退要求无 ACTIVE 签约，并在同一事务内把 PENDING 签约置 TERMINATED、订单置 `REFUNDED/CLOSED`；
  - 订单累计 `refundedPointsAmount` 作为乐观锁，双击/并发退款只有一次成功；退款入账走 `PointsService.refundTx`，与订单状态、退款记录同事务提交；
  - 积分流水类型 `REFUND`，冲减「累计消费」而非计入「累计赚取」；每次退款写 `service_package_refunds` 对账。

### 路由
- 管理端按 `/backend` 前缀约定；用户端 `/enterprise/service-packages`、`…/quote`、`…/:id/purchase`、`…/mine`；「我的套餐」独立菜单路由（如 `/my-packages`）。

## 六、交付闭环状态机

```
积分购买 PAID
  → 待匹配 PENDING_MATCH（存在未指定服务商的交付项）
  → 签约中 SIGNING（平台已发起，服务商待确认/部分生效）
  → 已签约 DELIVERED（全部交付项签约生效；内部键 DELIVERED，界面显示「已签约」）
  → 已关闭 CLOSED（整单退款/终止）
```
部分退款不改变交付状态，订单记 `PARTIAL_REFUNDED` 并继续跟踪签约；整单退才关闭订单。
套餐只做一次性签约交付，**不产生交付周期、不做到期管理**；`unit` 仅用于价格展示。

发起方式：
- **人工主持**：交付管理队列逐项匹配服务商 → 「主持发起签约」。
- **预绑自动**：套餐 `autoInitiate=true` 且交付项预绑 → 购买后自动发起（仅 PENDING）；**预设不等于确认，必须等服务商确认后才进入 ACTIVE**；失败转人工。

更换主体（服务商否决/迟迟不确认）：
- 原 Offer 撤销（terminate 旧签约）→ 平台选新优质服务商重新发起 → 明细回填新 contractId。
- 「迟迟不确认」由交付队列按 PENDING 时长标红提醒，**平台人工主持更换，不做自动超时撤单**（自动撤销风险高）。

## 七、平台后台「服务套餐」板块（两个页签）
1. **套餐目录**：CRUD。表单含板块、名称、简介、人民币价（元）、计价单位（仅展示，不参与周期/到期）、包含服务（多行）、积分价实时预览、**交付配置区**（先选分配方式：**预设服务商**＝逐项选定优质服务商，可选「购买后自动发起」（自动发起仍须服务商确认，不会自动生效）；**人工分配**＝这里只配交付项，订单产生后再到「交付管理」逐项匹配。两种方式二选一，不允许混合）、交付说明、纳税人档（财税）、**每企业限购**、上下架、排序。
2. **交付管理**：采购订单队列 → 展开交付明细 → 逐项匹配服务商（下拉＝该类目已备案优质服务商）→ 「主持发起签约」（批量建 PENDING）→ 跟踪生效；支持「更换服务商」（原 Offer 撤销 + 重新发起）；全部生效标记「已签约」；支持**部分退款**（输入积分，订单与交付保留）与**整单退款**（退回剩余全部并关闭订单），并展示已退/可退积分。
- 进入即加载、变更自动重拉（不加手动刷新按钮）。

## 十、规则对齐与配套同步
- 独占类目（财税/出海/营销/资产细项）每交付项一家服务商；多服务商板块（物流/法律/知产/灵工/供销/IT）可多家。
- 主持签约复用备案校验：未备案/不承接该细项者不可匹配。
- 服务商确认沿用现有流程，平台只主持发起 + 跟踪 + 换主体，不替代服务商确认。
- contracts 新增 zod schema/API 操作 → rebuild dist + 重生成 `docs/api/openapi.json`（`api:docs:check` 逐字节）；菜单/多语言字典/功能目录同步；守卫 `check:architecture`、`api:docs:check`、tsc、eslint 全过。
- 行尾：TSX/TS 为 LF，`globals.css` 为 CRLF。

## 十二、方案评估与风险

### 复用优势（落地成本低）
- 积分 `debit/credit` 原子可审计；签约 `create/confirm/terminate` 成熟且**平台管理员已有 terminate/remove 权限**（`contracts.service.ts:574/541`），换主体/Offer 撤销零新增权限模型。
- 服务商候选 `providerDirectory/candidates` 现成；后台板块/页签、共享面板插入点成熟。

### 风险与边界（需关注）
1. **平台代发起校验复用**：现有 `create` 强绑 `ENTERPRISE_USER` + 调用者企业；须抽公共校验供 `initiateByPlatform` 复用，防复制漂移。中等工作量。
2. **自动发起失败降级**：预绑服务商可能已停用/不承接/独占被占 → 自动发起失败。口径：购买事务只落订单+明细，自动发起 best-effort，失败转「待匹配」人工兜底，**不阻断购买**。
3. **已生效签约换主体**：terminate 不拦业务单据，remove 拦。建议换主体仅针对未生效（PENDING）或无业务单据的签约；已生效且产生单据的走解约 + 线下处理。
4. **服务商否决无独立状态**：复用 TERMINATED + note 标注，避免改签约状态机波及全系统。
5. **汇率所见即所扣**：购买弹窗实时 quote 再扣，防浏览→购买间隙汇率变动导致不一致。
6. **退款**：已支持部分退/整单退；整单退要求无生效签约并在同事务撤销待确认签约。退款入账与订单累计已退同事务提交，乐观锁防重复退款。已生效且需退款的场景仍走「解约 + 线下处理」。
7. **限购并发**：下单事务内对套餐目录行 `FOR UPDATE` 后复算企业已购数，同企业多账号并发购买不会穿透；事务前的计数检查仅用于快速失败。
8. **超时不自动撤单**：仅队列标红提醒 + 人工换主体，规避自动撤销风险。

### 复杂度
中大型功能：后端 3 服务 + 3 表 + Contract 增补 + 契约；前端后台 2 页签 + 共享面板 + 10 板块插入 + 我的套餐页 + 购买弹窗。建议按 §十一 分阶段交付（先目录+展示+购买，再交付闭环+换主体+退款）。
