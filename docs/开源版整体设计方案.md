## 一、定位与总体架构

开源版 = **独立用户体系的企业服务工作台 + 商务社交网络**，与 AIPDD/AIworkin 的关系从「账号从属」降级为「可选的上游能力」：

```
浏览器 ── Next.js 前端 ──┐
                          ├─ Hono 后端 ── MySQL 本地库(enterprise)   ← 全部业务/社交/用户数据
                          │        │
                          │        └─ AiworkinClient ──(用户绑定的 AIPDD APIKey)──→ AIworkin / AIPDD 上游
                          │                              · 企业板：发布需求 / 发布服务 / 服务商资格申请
                          │                              · 社交板：通用发布需求 / 发布服务（同步上游，可选）
                          │                              · 模型配置随绑定 Key 整体贯通
                          ├─ 用户自助中心：注册 / 登录 / 找回密码 / 改密 / 换绑 / 注销 / 本系统 APIKey 管理
                          └─ 平台管理后台（本地管理员）：站点设置 / 注册方案 / 用户封禁 / 密码重置兜底
```

- 原 Enterprise 的 50 余个业务模块（OA、CRM、税务、多维表格、RPA、GEO 等）**整体保留移植**——均为本地数据 + 用户自带凭据架构。
- SNS 的社交能力作为**社交板块**移植进 Enterprise，前端界面融合进 Enterprise 的 Ant Design 风格，**丢弃 SNS 原有样式**；后端逻辑从 NestJS 移植进 Enterprise 的 Hono 体系。
- 三件事必须走上游：**发布需求、发布服务、服务商资格申请**（审核也在 AIworkin 完成）；其余功能全部本地闭环。

### 上游系统说明

AIworkin 与 AIPDD 是同一套系统的两个应用，用户底层一致，**APIKey 通用**。本地凭证模型只需保存一把「AIPDD APIKey」即可同时访问账号资料与 AIworkin 平台能力。

## 二、数据库方案（PostgreSQL → MySQL）

| 项 | 方案 |
|---|---|
| 连接 | `mysql://enterprise:****@127.0.0.1:3306/enterprise`；`.env.example` 只放占位符，实际密码仅存本机 `.env`（已验证本机 MySQL 8.0.29 连通） |
| Prisma | `datasource db { provider = "mysql" }`；JSON 字段使用 MySQL 原生 JSON 类型 |
| 迁移基线 | **丢弃两个源项目的 PG migrations 历史**，用 `prisma migrate diff --from-empty --to-schema-datamodel` 生成全新 `0001_init` MySQL 初始迁移（Enterprise 245 模型 + SNS 27 模型合并后一次建库） |
| 表前缀 | SNS 表不带 schema（MySQL 无 multiSchema 习惯），统一加 `sns_` 前缀落入同一 `enterprise` 库 |
| 字符集 | `utf8mb4` / `utf8mb4_unicode_ci`；沿用现有 `@map` snake_case 命名 |
| 逐项核对 | ① VarChar 组合索引超 3072 字节时加前缀长度；② `DateTime @default(now())` 兼容性；③ `seed.ts` 中 PG 方言 SQL 改写；④ SNS 的 `multiSchema` 配置移除；⑤ Boolean/Int 语义统一 |
| 健康检查 | `/health/ready` 连本地 MySQL 验证，不验证上游 |

## 三、独立用户体系与账户生命周期

### 3.1 本地用户表与登录

新增 `users` 表：

```
id / username / email / phone / password_hash(bcrypt，手机验证码注册可空)
/ email_verified(0/1) / phone_verified(0/1)
/ status(ACTIVE|BANNED|DELETED) / ban_reason / must_change_password(0/1)
/ token_version(改密/重置后失效旧会话) / last_login_at
/ avatar / intro / lang / role(USER|PLATFORM_ADMIN) / created_at / updated_at
```

- **登录**：本系统自行签发 JWT（HS256，`JWT_SECRET` 本地管理）。删除原「校验 Java 签发令牌 / SSO 跨站登录 / 上游实时拉档案」链路（Enterprise `auth.service.ts`、`dev-session.ts`、`sns.client.ts` 账号部分，SNS `middleware.ts` 的 `aiworkin_token` 验签）。
- `UserDirectory`（上游用户缓存）退化为本地 `users` 投影，SNS 的 `UserMirror`（名录镜像）改为从本地 `users` 生成，各模块 `createdBy → 显示名` 查询逻辑不改代码。
- **封禁**：`status=BANNED` 即时拦截登录与全部业务接口（含社交板块），由平台后台操作并写 `AuditLog`。SNS 原有的 `UserSuspension`（站内行为封禁）保留为社交板块级封禁，与平台级封禁分层。

### 3.2 注册方案（管理员后台可配）

`SystemSetting` 键 `register_mode`：`USERNAME | EMAIL | PHONE`（可多选启用，默认 USERNAME）：

| 方式 | 要求 |
|---|---|
| 用户名+密码 | 开箱即用，无外部依赖（开源版默认） |
| 邮箱+密码 | 需后台配置 SMTP（host/port/账号/密码/发件人），凭据 AES-256-GCM 加密存储；未配置时不可选 |
| 手机号+验证码 | 需后台配置**阿里云短信服务**：AccessKeyId、AccessKeySecret（加密存储）、短信签名、验证码模板 ID、每日发送上限；未配置完整时该方式在注册页禁用并在后台给出提示 |

阿里云短信客户端复用 Enterprise 现有 `aliyun-*` 模块的凭据加密与调用模式；验证码存本地表（5 分钟有效、60 秒重发限制、图形验证码或行为验证防刷）。

### 3.3 AIPDD APIKey 绑定（N:1）

「一个 APIKey 可被多个用户绑定」，两张表：

```
aipdd_keys
├─ id
├─ key_fingerprint   SHA-256 指纹，UNIQUE，用于多用户归并到同一把 Key
├─ key_cipher        AES-256-GCM 加密存原文（EXTERNAL_CRED_KEY 派生密钥），接口永不回显
├─ aipdd_user_id     绑定成功时从上游解析出的 AIPDD 用户身份
├─ aipdd_profile     JSON 快照（昵称/头像/等级等）
└─ status(ACTIVE|REVOKED) / last_verified_at / created_at

user_aipdd_bindings
├─ user_id  FK→users，UNIQUE（一个用户只绑一把 Key）
├─ key_id   FK→aipdd_keys
└─ bound_at
```

**绑定流程**：用户填入 AIPDD APIKey → 后端临时以 `Bearer <key>` 调 AIworkin（`GET /user/info`）验真 → 解析出 AIPDD 用户 ID 后加密落库 → 绑定完成，该本地用户与 AIPDD 用户建立对应关系。多个本地用户填同一把 Key 时按 `key_fingerprint` 归并，天然形成 N:1。

**凭证解析器（全系统唯一入口）**：

```
请求进入 → 当前本地用户 → user_aipdd_bindings → 解密 key_cipher → Bearer 转发 AIworkin
                              └─ 未绑定 → 业务错误码「请先在个人设置中绑定 AIPDD APIKey」
```

### 3.4 模型配置贯通

RPA / AI 调用 / Workbuddy / GEO 等模块原有的「平台 API Key 内省 / 模型 Key 下发」（`model-key.service.ts`）统一改为从用户绑定的 `aipdd_keys` 取凭证——**只要绑定了 AIPDD APIKey，上游模型配置整体一致**，无需二次配置。

### 3.5 Key 体系统一（两种 Key，职责分明）

开源版全系统只保留两种 Key：

| | 本地 APIKey（用户自助申请） | AIPDD APIKey（上游绑定） |
|---|---|---|
| 签发方 | **本系统**签发，前缀 `ek_` | AIPDD/AIworkin 账号侧（`sk-` 形态），本系统只收不代申 |
| 用途 | **调用本项目**：`/api/v1/*` REST 机器通道、MCP Server、AI 代理操作授权 | **本项目调上游**：发布需求 / 发布服务 / 资格申请 / 模型配置 |
| 存储 | 只存 SHA-256 哈希（不可逆），签发时一次性展示明文 | AES-256-GCM 密文（需代用户调上游，必须可解） |
| 生命周期 | 用户自助：申请 / 重命名 / 查看用量与最近调用 / 吊销 / 删除 | 用户自助：绑定 / 解绑 / 换绑；平台可全局禁用 |

**合并改造点（对应源项目三处 Key 功能）**：

1. 原 Enterprise `api_keys` 表（`ek_` 机器通道）与原 SNS `api_keys` 表（scopes / 日限额 / 调用量）**合并为统一 `api_keys` 表**，字段取并集：`id / user_id / name / key_prefix(ek_) / key_hash(UNIQUE) / scopes(JSON，默认 ["READ"]) / status(ACTIVE|REVOKED) / rate_limit_day(默认 2000) / call_count / last_used_at / revoked_at / created_at`；历史 `key_cipher` / `remote_id`（sk_ 镜像列）整列删除——AIPDD Key 独立存 `aipdd_keys`，不混入本表。
2. SNS 的 `AiGrant`（AI 发送类动作授权白名单）与 `ApiCallLog`（调用审计，区分 rest / mcp 通道）挂到统一 `api_keys` 下原样迁移。
3. **「申请平台 Key」功能取消**：原 `apikey.service.ts` 的代 AIPDD 账号侧申请/查询（`/api_key/create`、`/api_key/list`）与 `model-key.service.ts` 的 testKey 兜底逻辑整段删除；GEO 采集 / 大数据查询 / 潜客挖掘等对「平台 Key」的引用统一改取用户绑定的 AIPDD Key（3.3 凭证解析器），前端对应申请入口移除，只保留「绑定 AIPDD APIKey」与「本系统 APIKey 管理」两个自助页。

### 3.6 账户自助全家桶（开源版一应俱全）

| 功能 | 方案 |
|---|---|
| 注册 | 按后台配置的三通道（3.2）；注册页展示用户名/密码强度规则与协议勾选；邮箱/手机号唯一性校验；可选邀请码归因（5.2 邀请） |
| 登录 | 账号（用户名/邮箱/手机）+密码，或验证码登录（需对应通道已配置）；记住登录（延长会话）；`must_change_password=1` 时登录后强制改密 |
| **找回密码·邮箱** | 「忘记密码」→ 填邮箱 → SMTP 发送重置链接（token 30 分钟有效、一次性），点击后设新密码；需后台已配置 SMTP |
| **找回密码·短信** | 手机号用户 → 阿里云短信发验证码 → 验证码重置；需后台已配置短信服务 |
| **找回密码·兜底** | 未绑定任何可用通道（典型为用户名注册）：提交申诉，管理员在后台**重置密码**（随机新密 + `must_change_password=1` 首登强改），全程写 `AuditLog` |
| 修改密码 | 登录态改密需验旧密码；成功后 `token_version+1`，所有旧会话/令牌即时失效 |
| 换绑邮箱/手机 | 新邮箱验证链接 / 新手机验证码确认后生效，验证完成前原渠道仍有效；目标已被占用时拒绝并提示（防抢绑） |
| 验证码/令牌服务 | 统一 `verify_codes` 表：`scene(REGISTER\|LOGIN\|RESET_PASSWORD\|REBIND) + channel(EMAIL\|SMS) + target + code_hash + expire_at + used_at`；5 分钟有效、60 秒重发、单目标日发送上限、错过 5 次作废；前置图形/行为验证码防刷；只存哈希不存明文 |
| 资料设置 | 头像、昵称、简介、语言偏好；社交资料扩展见 5.2 |
| 登录安全 | `login_logs`（时间/IP/UA/成功失败）；同账号连错 5 次锁定 10 分钟；登录/注册/验证码接口按 IP 限流 |
| 账号注销 | 用户自助注销 = 软删除 `status=DELETED`，可配冷静期（默认 15 天，期间重新登录可撤销）；生效后显示名匿名化为「已注销用户」，其已发布内容保留（延续 SNS 匿名口径），注销策略后台可配 |
| 通知渠道 | 站内信必有兜底（与社交 `Notification` 统一）；邮件通知为可选开关，随 SMTP 配置可用性 |

## 四、发布需求 / 发布服务（两个板块，一套上游通道）

### 4.1 企业板块（专业发布）

沿用 Enterprise 现有实现（`demand.service`、`ProviderServiceListing`、`ProviderApplication`，均已按 `token` 参数调用 `AiworkinClient`），只替换凭证来源为 3.3 的绑定 Key。幂等键（`^[A-Za-z0-9_-]{16,100}$`）、GET 重试 / 写操作幂等约束、`demand-sync` 状态回同步、类目字典机制全部原样保留。企业身份（`EnterpriseProfile`）、服务商资格申请仍面向有资质场景，审核状态以上游为准，本系统仅镜像展示。

### 4.2 社交板块的通用发布（新增，本轮方案核心增量）

SNS 原版「发布需求 / 发布服务」只是跳转 AIworkin 前端；开源版改为**站内原生、人人可用**：

- **无资质门槛**：不要求企业认证、不要求服务商资格，任何本地注册用户即可发布——这是与企业板块专业发布的唯一差别。
- 新增 `sns_listings` 表（社交板供求帖）：

```
id / author_user_id / type(DEMAND|SERVICE) / title / description(text)
/ tags / money_mode / amount_min / amount_max / currency / region(province/city)
/ contact_note(选填，联系方式说明)
/ status(LOCAL_PUBLISHED | UPSTREAM_SYNCING | UPSTREAM_LIVE | UPSTREAM_REJECTED | SYNC_FAILED)
/ aiworkin_demand_no / aiworkin_listing_no   上游回流关联（审核通过后回填）
/ published_upstream(0/1)  -- 是否同步发布到 AIworkin
/ created_at / updated_at
```

- **两段式发布**：
  1. 本地发布——任何用户可直接发布，进入社交「供求广场」信息流，可被好友/陌生人浏览、私信对接（沟通走站内私信，与 SNS 招聘专区同一口径）；此段**不需要** APIKey。
  2. 同步发布到 AIworkin——帖子上勾选「同步发布到 AIworkin 平台」，经 3.3 凭证解析器以绑定 Key 调上游发布接口（需求→发布需求接口；服务→发布服务接口），上游审核状态由同步任务回写 `status`；未绑定 Key 时该开关置灰并提示绑定。此段遵循既定原则：**必须绑定 AIPDD APIKey 才能完成**。
- 上游侧审核、撮合、成交均与 AIworkin 现有规则一致；本系统只镜像状态。
- 企业板块与社交板块共用 `AiworkinClient` 与凭证解析器，发布入口、字段口径保持同构（类目字典、计价方式、服务地区三态 NATIONWIDE/REGION/RADIUS）。

## 五、SNS 社交板块融合

### 5.1 融合原则

| 维度 | 处理 |
|---|---|
| 样式 | **丢弃 SNS 原有视觉（aiworkin.com 蓝白风格）**，页面全部重写为 Enterprise 的 Ant Design 6 / Pro Components 主题；只保留 SNS 的信息架构与交互逻辑 |
| 后端 | NestJS 模块逻辑移植为 Enterprise Hono 的 `social/` 模块组（profile / relationship / post / group / mail / resume / network / hiring / listing(供求) / notification / moderation） |
| 前端 | 在 Enterprise Next.js 应用内新增一级路由 `/social/*`（发现 / 动态 / 小组 / 私信 / 人脉 / 简历 / 招聘 / 供求广场 / 我的主页），导航栏增设「社交」入口；SNS 的 zh-CN/en-US i18n 字典随模块迁移 |
| 数据 | 27 个 SNS 模型全部并入本地 MySQL `enterprise` 库，表名加 `sns_` 前缀；`userId` 指向本地 `users.id` |
| 鉴权 | SNS 原「验 AIworkin JWT、不建用户表」整段废除，统一走本地 JWT + 用户体系（见第三章） |
| 上游 | SNS 对 AIworkin 的 skills/demands/services 实时读取、60s 缓存降级、fixtures 回退等逻辑：凡属「展示上游数据」的保留（凭证换成绑定 Key）；凡属「跳 AIworkin 前端发布」的改为 4.2 的站内原生发布 |

### 5.2 社交板块功能清单（P0 全量移植）

| 模块 | 内容 | 本地/上游 |
|---|---|---|
| 个人资料 | SNS 资料扩展（`SnsProfile`）、社交邮箱地址、联系我卡（手机/邮箱/微信/社媒自填） | 本地 |
| 关系 | 好友申请/好友/关注/屏蔽（`FriendRequest`/`Friendship`/`Follow`/`Block`） | 本地 |
| 动态 | 纯文字短内容，可见性 PUBLIC/FRIENDS 口径（`Post`） | 本地 |
| 小组 | 豆瓣式讨论组：公开/私密、自由加入/组长审批、主帖/楼层、逐条匿名（`Group`/`GroupMember`/`GroupTopic`/`GroupReply`） | 本地；**AI 一律不参与**（延续 SNS 约束） |
| 私信 | 双人会话聚合 + 消息（`Mailbox`/`MailThread`/`Message`） | 本地 |

## 八、安全设计要点

1. AIPDD APIKey、阿里云 AK/SK、SMTP 密码等一切外部凭据：AES-256-GCM 加密（`EXTERNAL_CRED_KEY` 派生），接口只回显掩码（如 `sk_****abcd`），永不返回明文/密文。
2. `key_cipher` 读取仅限凭证解析器内部调用，业务代码不得直接获取解密结果，调用上游后立即销毁内存引用。
3. 密码 bcrypt(cost≥10)；登录、注册、验证码接口限流与失败锁定；**重置 token / 验证码只存哈希、一次性、短时效**，用后即焚；改密/重置通过 `token_version` 使全部旧会话即时失效。
4. 社交匿名口径不变：匿名主帖/楼层读接口不回显身份，真实 userId 仅用于删除权限。
5. 生产 `AUTH_COOKIE_SECURE`、CORS 白名单、`DEV_AUTO_LOGIN` 在 production 模式代码级禁用（源项目已有机制，保留）。
