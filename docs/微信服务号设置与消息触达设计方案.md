# 微信服务号设置与消息触达设计方案

> 状态：方案稿（2026-11-10）。范围：平台管理后台「微信服务号设置」+ 服务号绑定 + 任务/回复类消息触达 + 移动端 H5 处理闭环。
> 本文只做设计，不含代码改动；实施批次与验收清单见第十、十一节。

---

## 一、需求拆解（你的原话 → 目标态）

| # | 需求要点 | 目标态 |
|---|---|---|
| 1 | 平台管理员可配置微信服务号 | 后台新增「微信服务号设置」栏目，维护 AppID / AppSecret / Token / EncodingAESKey / 加密模式，支持连通性测试；密钥密文存储、永不回显 |
| 2 | 可配置服务号的模板映射 | 后台把「业务事件」映射到微信模板 ID 与字段变量（如任务标题、发起人、时间），支持模板同步、字段预览、测试发送、启停 |
| 3 | 用户关注服务号后，接收任务通知、信息回复等必要唤醒 | 站内通知照旧必达；绑定用户额外收到模板消息（主通道），48 小时会话内可补发客服消息；全部落推送记录，可重试、可审计 |
| 4 | 用户在手机 H5 上处理对应事务 | 模板消息/自定义菜单/被动回复的链接统一指向 `/m/*` 移动端页面；支持免登录（微信网页授权）与任务审批、客服回复等快捷处理 |
| 5 | 管理员可配置服务号菜单、关注提示 | 后台可视化菜单编辑器（3 个一级 × 5 个二级，view / click），发布到微信、拉取当前菜单；关注欢迎语、关键词回复、默认唤醒回复均可配 |
| 6 | 系统右上角二维码图标，关注即绑定 UserID | 顶栏新增二维码入口：未绑定展示场景二维码，扫码关注/已关注扫码后自动把 `openId` 与当前登录 `userId` 绑定；已绑定展示状态与解绑 |

**边界说明**

- 本方案针对**平台级单个微信服务号**（平台管理员配置），不做每个企业各自接一个服务号；多服务号/多公众号路由留作后续扩展。
- 微信消息是「尽力触达」，站内消息才是「必达」；产品文案不能承诺微信 100% 送达（用户可能未关注、取关、免打扰、接口限频）。
- 只发**与当前用户相关的服务通知**，不做营销群发，避免模板消息滥用与封号风险。

## 二、现状盘点

### 2.1 可直接复用的地基

| 能力 | 现有位置 | 复用方式 |
|---|---|---|
| 公众号 access_token 获取 | `backend/src/content/agent-assistant.channel.ts` | 抽出通用客户端，补缓存与并发合并 |
| 公众号回调验签 / AES 解密 / XML 解析 | 同上（`wechatMpReceive`、`decryptWechatXml`） | 抽出 `wechat-mp.client.ts`，本方案回调直接复用 |
| 客服消息发送 | 同上（`/cgi-bin/message/custom/send`） | 作为模板消息的会话内兜底通道 |
| 开放平台扫码登录客户端 | `backend/src/account/wechat-oauth.ts` | 复用 `httpRequest` 与错误归一化写法；网页授权另写轻量客户端 |
| `system_settings` + 密文配置模式 | `backend/src/account/account-settings.service.ts` | 同样的「JSON 配置 + AES-GCM 密文 + 空串保留原值 + 对外只看是否已配」模式 |
| 全站通知唯一写入口 | `backend/src/notifications/notification.service.ts` | 在 `notify/notifyMany` 落库后异步触发微信推送（可选依赖，不阻塞主流程） |
| 顶栏动作区 | `frontend/src/components/pro/pro-layout.tsx` `actionsRender` | 在 `NotificationBell` 左侧插入二维码入口 |
| 无壳移动端页面 | `frontend/src/components/app-shell.tsx` `SHELL_FREE_PREFIXES` 已含 `/m/` | 新增 `/m/inbox`、`/m/inbox/[id]` 即可不带后台侧栏 |
| 二维码生成（前端） | 前端依赖 `qrcode` v1.5.4 | 场景二维码本身由微信 `qrcode/create` 返回图片 URL，前端只展示，无需本地生成 |
| 站点地址解析 | `backend/src/common/site-url.ts`（`resolveSiteUrl` / `joinSiteUrl`） | 模板消息 URL、菜单 URL、网页授权回调都基于站点地址拼接 |

### 2.2 缺口（本方案要补的）

1. 没有服务号专属配置：现有微信配置分属「账号与登录」（开放平台扫码登录）和「AI 客服渠道」（企业自备公众号），**都不是平台级服务号**。
2. 没有绑定关系：`AccountBinding` 面向第三方登录（`WECHAT_OPEN`），不能表达「关注状态、取关时间、48 小时窗口、解绑」。
3. 没有场景二维码：静态二维码无法把扫码人对应到某个登录用户，必须走 `QR_STR_SCENE` + `subscribe`/`SCAN` 事件。
4. 没有模板映射与发送链路：无模板同步、字段变量、发送日志、失败重试、限频与免打扰。
5. 没有菜单与关注回复：无菜单草稿/发布、无关注欢迎语、无关键词与默认唤醒回复。
6. 没有移动端处理页：`/m/` 下目前只有订单相关页面，缺「消息收件箱 + 事务处理」。
7. 没有顶栏绑定入口：用户即使关注了，也无法把微信身份和站内账号关联起来。

### 2.3 微信侧硬约束（设计前提）

| 约束 | 影响 |
|---|---|
| 模板消息、自定义菜单、客服接口需要**已认证服务号** | 后台需明确展示账号类型与「未认证」时的能力降级说明 |
| 服务器回调必须公网 **80/443**，微信 5 秒内收不到响应会重试 3 次 | 回调先极快回 `success`，业务处理异步化；`MsgId` 必须幂等 |
| 模板消息不依赖 48 小时窗口；客服消息仅限用户最后互动后 48 小时内 | 模板消息为主，客服消息只做会话内补发 |
| 自定义菜单最多 3 个一级、每级最多 5 个二级 | 后台编辑器按此限制校验 |
| 获取 access_token 的出口 IP 需加入公众号后台 IP 白名单 | 部署文档与后台「连通性测试」要给出明确报错 |
| 一个公众号只能配置一个服务器 URL | 若该服务号已被「AI 客服」占用，需要统一回调分发（见 12.3） |
| 关注欢迎语只能有一条，关键词回复受公众号后台规则约束 | 服务器模式下由本系统被动回复接管，需在公众号后台关闭同类自动回复避免冲突 |

## 三、总体设计

### 3.1 分层结构

```
┌──────────────────────────── 平台管理后台 ────────────────────────────┐
│ 微信服务号设置（基础配置 / 模板映射 / 菜单 / 关注与绑定 / 推送记录） │
└───────────────────────────────┬──────────────────────────────────────┘
                                │ /api/backend/enterprise/admin/wechat-mp/*
┌───────────────────────────────▼──────────────────────────────────────┐
│                        WechatMpModule（后端）                        │
│  SettingsService   Client   BindingService   PushService   MenuService│
└───────┬───────────────────┬───────────────────────┬──────────────────┘
        │                   │                       │
        │ system_settings   │ 微信 HTTPS API        │ 站内通知事件
        │ + 4 张业务表      │ (token/qrcode/msg/menu)│ (NotificationService)
        ▼                   ▼                       ▼
   数据库（Prisma）      微信服务号            站内铃铛 + /m/* H5
                                ▲
                                │ 回调 /api/public/wechat-mp/callback
┌───────────────────────────────┴──────────────────────────────────────┐
│ 用户侧：顶栏二维码绑定入口、微信会话内被动回复、模板消息跳转 H5      │
└──────────────────────────────────────────────────────────────────────┘
```

### 3.2 消息通道选型

| 通道 | 触发时机 | 用途 | 约束 |
|---|---|---|---|
| **模板消息**（主） | 业务事件发生（任务派发、客服回复、审批待办…） | 唤醒用户，点开进 H5 处理 | 需模板 ID 与字段映射；受日上限与免打扰控制 |
| **客服消息**（兜底） | 用户在 48 小时内与服务号有互动 | 模板不可用/字段不足时补发富文本 + 链接 | 超出 48 小时直接跳过并记 `skipped` |
| **被动回复**（即时） | 用户关注、发关键词、发任意消息 | 欢迎语、待办摘要、默认唤醒 | 5 秒内必须响应；文本长度受限 |
| **站内通知**（必达） | 所有业务事件 | 铃铛未读、消息中心 | 与应用内现有逻辑一致，不依赖微信 |

### 3.3 产品口径

1. **绑定是显式动作**：用户在登录状态点顶栏二维码 → 扫码关注/已关注扫码 → 绑定成功；不做「扫码即静默登录」。
2. **关注不等于绑定**：只有通过带场景值的二维码或站内绑定流程，才建立 `openId ↔ userId` 关系。
3. **站内与微信解耦**：微信推送失败不影响站内通知；推送记录独立可查、可重试。
4. **可随时解绑/取关**：用户解绑后立即停止微信推送；微信侧取关自动标记 `subscribed=false`，重新关注后恢复推送（绑定关系保留）。
5. **不重复打扰**：同一用户同一事件在 `dedupeSeconds` 内只推一次；免打扰时段与日上限内只落站内。

**读写规则**

- `appSecret` / `encodingAesKey` 入参为空串 = 保留原值；后台读取只返回 `secretConfigured: true/false`，永不回显明文。

- 配置读取带缓存（进程内 30 秒），保存后主动失效；多实例部署时以数据库为准，缓存仅作短时加速。

### 4.2 Prisma 新增模型（迁移 `0059_wechat_mp`）

> 当前最新迁移为 `0058_workflow_triggers`，本方案迁移编号顺延为 `0059_wechat_mp`。

```prisma
/// 平台服务号绑定：一个站内用户至多绑定一个服务号 openId
model WechatMpBinding {
  id                Int       @id @default(autoincrement())
  userId            String    @unique @map("user_id") @db.VarChar(64)
  openId            String    @unique @map("open_id") @db.VarChar(64)
  unionId           String?   @map("union_id") @db.VarChar(64)
  nickname          String    @default("") @db.VarChar(120)
  avatarUrl         String    @default("") @map("avatar_url") @db.VarChar(500)
  subscribed        Boolean   @default(true)
  subscribedAt      DateTime? @map("subscribed_at")
  unsubscribedAt    DateTime? @map("unsubscribed_at")
  /// 用户主动回复「退订」后关闭微信推送，但保留绑定关系
  pushMuted         Boolean   @default(false) @map("push_muted")
  /// 最近一次用户互动（关注/发消息/点菜单），用于 48 小时客服消息窗口判定
  lastInteractionAt DateTime? @map("last_interaction_at")
  /// qrcode | admin | migrate
  source            String    @default("qrcode") @db.VarChar(24)
  createdAt         DateTime  @default(now()) @map("created_at")
  updatedAt         DateTime  @updatedAt @map("updated_at")

  @@index([unionId])
  @@index([subscribed, updatedAt])
  @@map("wechat_mp_bindings")
}

/// 一次性绑定场景值：带参二维码扫码后用它反查 userId
model WechatMpBindScene {
  id        Int       @id @default(autoincrement())
  scene     String    @unique @db.VarChar(64)
  userId    String    @map("user_id") @db.VarChar(64)
  expiresAt DateTime  @map("expires_at")
  usedAt    DateTime? @map("used_at")
  createdAt DateTime  @default(now()) @map("created_at")

  @@index([userId, createdAt])
  @@index([expiresAt])
  @@map("wechat_mp_bind_scenes")
}

/// 微信推送记录：每次模板/客服消息尝试都落一条，便于排查与重试
model WechatMpMessage {
  id         Int       @id @default(autoincrement())
  userId     String    @map("user_id") @db.VarChar(64)
  openId     String    @map("open_id") @db.VarChar(64)
  /// template | custom | passive
  kind       String    @db.VarChar(16)
  eventKey   String    @default("") @map("event_key") @db.VarChar(48)
  templateId String    @default("") @map("template_id") @db.VarChar(64)
  title      String    @default("") @db.VarChar(200)
  content    String    @default("") @db.Text
  link       String    @default("") @db.VarChar(500)
  /// pending | sent | failed | skipped
  status     String    @default("pending") @db.VarChar(16)
  errcode    Int?
  errmsg     String    @default("") @db.VarChar(300)
  attempts   Int       @default(0)
  /// 微信返回的 msgid（模板消息）
  msgId      String    @default("") @map("msg_id") @db.VarChar(64)
  entityType String    @default("") @map("entity_type") @db.VarChar(32)
  entityId   String    @default("") @map("entity_id") @db.VarChar(64)
  sentAt     DateTime? @map("sent_at")
  createdAt  DateTime  @default(now()) @map("created_at")

  @@index([userId, createdAt])
  @@index([status, createdAt])
  @@index([eventKey, createdAt])
  @@map("wechat_mp_messages")
}

/// 回调幂等：微信会重试，同一 MsgId 只处理一次
model WechatMpInboundEvent {
  id        Int      @id @default(autoincrement())
  msgId     String   @unique @map("msg_id") @db.VarChar(96)
  openId    String   @map("open_id") @db.VarChar(64)
  msgType   String   @default("") @map("msg_type") @db.VarChar(24)
  event     String   @default("") @db.VarChar(32)
  eventKey  String   @default("") @map("event_key") @db.VarChar(64)
  payload   String   @db.Text
  createdAt DateTime @default(now()) @map("created_at")

  @@index([openId, createdAt])
  @@map("wechat_mp_inbound_events")
}
```

**设计取舍**

- 绑定关系独立成表，不往 `Account` 加列，也不复用 `AccountBinding`：关注状态、取关、48 小时窗口是服务号独有语义。
- `openId` 全局唯一：同一微信只能绑一个站内账号，防冒绑；`unionId` 只做索引，便于未来多应用识别同一微信。
- `WechatMpBindScene` 一次性且带 TTL（默认 5 分钟），用后置 `usedAt`，避免二维码被转发后反复绑定。
- 推送记录保留 180 天（定时任务清理），入站事件保留 30 天。

### 4.3 事件映射（后台「模板映射」的可选项）

事件键由「业务模块.动作」组成，后台可逐个启停、选模板、配字段。

| eventKey | 触发点（现有通知写入处） | 建议模板字段 |
|---|---|---|
| `task.assigned` | 任务派发（任务中心各来源接入时） | 任务标题 / 发起人 / 截止时间 |
| `task.due` | 定时扫描「即将到期/已逾期」 | 任务标题 / 剩余时间 / 截止时间 |
| `task.status` | 任务状态变更（完成/驳回） | 任务标题 / 新状态 / 操作人 |
| `service_desk.reply` | 客服工单客服回复（`service-desk.service.ts`） | 工单标题 / 回复摘要 / 客户名 |
| `service_desk.assign` | 工单分配 | 工单标题 / 分配人 / 优先级 |
| `oa.approval` | OA 审批待办（`oa.service.ts`） | 审批标题 / 发起人 / 类型 |
| `oa.result` | OA 审批结果 | 审批标题 / 结果 / 审批人 |
| `account.security` | 账号安全提醒（异地登录、改密、换绑） | 提醒类型 / 时间 / 设备 |
| `platform.notice` | 平台公告 | 公告标题 / 发布时间 |
| `question.reply` | 专题大厅回复/被采纳 | 问题标题 / 回复人 / 摘要 |
| `collab.mention` | 协作中 @ 提及 | 来源标题 / 提及人 / 摘要 |

**事件键解析优先级**

1. `NotificationService.notify` 的入参若带显式 `push.eventKey`（新增可选字段），直接用；
2. 否则用 `category` 做默认映射（如 `service_desk` → `service_desk.reply`，`oa` → `oa.approval`，`account` → `account.security`）；
3. 再按 `entityType` 细化；仍无映射则只发站内，不推微信（记 `skipped: no_mapping`）。

这样不需要一次性改完所有通知调用点：P0 只在 4 个关键调用点补 `push.eventKey`，其余靠默认映射逐步补齐。

### 5.2 微信客户端（`wechat-mp.client.ts`）

| 能力 | 微信接口 | 说明 |
|---|---|---|
| access_token | `GET /cgi-bin/token` | 进程内缓存，提前 5 分钟刷新；并发请求合并（single-flight）；失败不缓存 |
| 生成带参二维码 | `POST /cgi-bin/qrcode/create` | `action_name=QR_STR_SCENE`，`scene_str=bind_<32hex>`，`expire_seconds=300`；返回 `ticket` 与图片 URL |
| 模板列表 | `GET /cgi-bin/template/get_all_private_template` | 后台「同步模板」按钮，结果只读展示，不落库（或短时缓存） |
| 发送模板消息 | `POST /cgi-bin/message/template/send` | `touser/template_id/url/data`；记录 `msgid` |
| 发送客服消息 | `POST /cgi-bin/message/custom/send` | 仅 48 小时窗口；文本 + `<a>` 链接 |
| 创建菜单 | `POST /cgi-bin/menu/create` | 发布草稿 |
| 查询菜单 | `GET /cgi-bin/menu/get` | 「拉取当前菜单」用于回填草稿 |
| 网页授权 | `GET /sns/oauth2/access_token` | P2 免登录用，`snsapi_base` 静默授权 |

**错误归一化**

| errcode | 含义 | 处理 |
|---|---|---|
| 40001 / 40014 / 42001 | token 无效或过期 | 清缓存，强制刷新后重试 1 次 |
| 40003 | openid 无效 | 标记绑定异常，停止重试 |
| 43004 | 用户未关注 | `subscribed=false`，推送记 `skipped` |
| 45009 | 接口调用超限 | 退避到下一分钟，记 `failed` 可重试 |
| 45047 | 客服消息超出 48h | 记 `skipped: out_of_window` |
| 40037 | template_id 无效 | 后台模板映射校验提示 |
| 其他 | — | 记 errcode/errmsg，最多重试 3 次 |

### 5.3 绑定流程

**生成场景二维码（用户已登录）**

```
POST /enterprise/wechat-mp/bind-scene
  → 校验服务号 enabled
  → 限频：同用户 30 秒 1 次、每日 5 次
  → 生成 scene=bind_<32hex>，落 wechat_mp_bind_scenes（TTL 5 分钟）
  → 调微信 qrcode/create（QR_STR_SCENE）
  → 返回 { scene, qrUrl, expiresAt }   // qrUrl 为微信 showqrcode 图片地址
```

**扫码回调处理**

```
POST /api/public/wechat-mp/callback（解密后 XML）
  ├─ Event=subscribe（未关注 → 关注）
  │    ├─ EventKey 形如 qrscene_bind_xxx：取 scene
  │    └─ 无场景值：普通关注，只走欢迎语
  ├─ Event=SCAN（已关注 → 扫码）
  │    └─ EventKey=bind_xxx：取 scene
  └─ 统一进入 BindingService.handleScene(openId, scene)
       ├─ scene 不存在 / 过期 / 已用 → 被动回复「二维码已失效，请在系统右上角重新获取」
       ├─ openId 已绑定其他 userId → 拒绝并提示「该微信已绑定其他账号」
       ├─ userId 已绑定其他 openId → 拒绝并提示「当前账号已绑定其他微信，请先解绑」
       └─ 成功：upsert 绑定，subscribed=true，lastInteractionAt=now
            → 被动回复欢迎/绑定成功文案 + H5 链接
```

**关键点**

- 场景值只在**创建它的用户登录态**下有效，二维码被转发也无法绑定到别人账号（scene 对应固定 userId）。
- 二维码 5 分钟过期，用户可点「刷新二维码」重新生成。
- 绑定成功后顶栏轮询 `GET /enterprise/wechat-mp/status`（3 秒一次，最多 2 分钟）自动切换为「已绑定」。
- 解绑：`DELETE /enterprise/wechat-mp/binding`，删除绑定行并记录审计；微信侧仍关注，但不再推送。
- 取关事件（`Event=unsubscribe`）：`subscribed=false`、`unsubscribedAt=now`；重新关注后 `subscribed=true`，绑定保留。

### 5.4 推送服务（`wechat-mp-push.service.ts`）

**触发方式**

- 在 `NotificationService.notify` / `notifyMany` 落库成功后，调用可选的 `wechatMpPush.onNotifications(rows, inputs)`；用 `void ... catch` 异步执行，**绝不阻塞业务主流程**。
- 定时类提醒（任务到期、审批超时）由对应定时任务显式调用 `pushByEvent(userId, eventKey, vars)`。

**单次推送决策链**

```
事件到达
  ├─ 服务号 enabled？否 → skipped(disabled)
  ├─ 用户绑定且 subscribed？否 → skipped(unbound / unsubscribed)
  ├─ 用户已退订（pushMuted）？是 → skipped(muted)
  ├─ 事件有模板映射且启用？否 → 尝试 48h 客服消息（若 customFallback）→ 否则 skipped(no_mapping)
  ├─ 免打扰时段？是 → skipped(quiet_hours)（站内已落库）
  ├─ 当日已达 dailyCap？是 → skipped(daily_cap)
  ├─ dedupeSeconds 内同 user+event+entity 已发？是 → skipped(duplicate)
  ├─ 模板消息发送
  │    ├─ 成功 → sent，记录 msgid
  │    └─ 失败 → 按错误码决定：刷新 token 重试 / 48h 客服消息兜底 / failed 待重试
  └─ 写 wechat_mp_messages
```

**变量渲染**

- 模板字段值支持 `{{变量}}`，内置变量：`title`、`body`、`userName`、`entityType`、`entityId`、`notificationId`、`createdAt`、`siteName`，以及调用方通过 `push.vars` 传入的业务变量（如 `taskTitle`、`senderName`）。
- 值做长度截断（微信字段一般 ≤200 字符）、去除换行、HTML 转义；缺失变量替换为空串并在记录里标注。
- `url` 相对路径统一用 `joinSiteUrl(await resolveSiteUrl(prisma), path)` 拼成绝对地址；仅允许站内相对路径或 `https://` 白名单域名，防开放跳转。

**重试**

- `failed` 且可重试（网络、45009、token 刷新后仍失败）→ 最多 3 次，退避 1 / 5 / 15 分钟，由每分钟一次的定时任务扫描。
- `skipped` 不重试；`40003`、`43004`、`45047`、`40037` 不重试。
- 后台「推送记录」提供单条手动重试（仅 failed/skipped 且绑定仍有效）。

### 5.5 回调处理（`wechat-mp-public.controller.ts`）

**GET（服务器配置验证）**

1. 校验 `signature = SHA1(sort(token, timestamp, nonce))`，时间戳偏差 > 5 分钟拒绝；
2. 安全模式下再用 `msg_signature` 校验并解密 `echostr`；
3. 原样返回解密后的 `echostr`，否则 403。

**POST（接收消息/事件）**

1. 验签（安全模式校验 `msg_signature`）；
2. AES-256-CBC 解密（key = `Base64Decode(EncodingAESKey + "=")`，IV = 前 16 字节，PKCS#7 去填充），校验尾部 AppID；
3. 解析 XML，得到 `MsgType` / `Event` / `EventKey` / `FromUserName` / `MsgId`；
4. **立即返回 `success`**（微信 5 秒限制），业务处理放到进程内异步队列（单进程 `setImmediate` + 并发上限；多实例时按 `MsgId` 幂等，重复处理无副作用）；
5. 若需要被动回复（关注/关键词/默认回复），必须在 5 秒内返回 XML，因此这类处理同步完成并直接响应，其余事件异步。

**幂等**

- 有 `MsgId` 的消息：`wechat_mp_inbound_events.msgId` 唯一键，插入冲突即视为重复，直接 `success`。
- 无 `MsgId` 的事件：用 `SHA1(FromUserName + CreateTime + Event + EventKey)` 作为 `msgId`。

**消息类型处理**

| 类型 | 处理 |
|---|---|
| `event/subscribe` | 解析场景值 → 绑定 → 关注欢迎语（可带 H5 链接） |
| `event/unsubscribe` | 标记取关，停止推送 |
| `event/SCAN` | 已关注扫码 → 绑定场景处理 |
| `event/CLICK` | 菜单 click 事件 → 按 key 返回待办摘要或跳转提示 |
| `event/VIEW` | 微信直接打开 URL，服务端不处理 |
| `text` | 关键词匹配 → 对应回复；无匹配 → 默认唤醒回复（待办数量 + 链接） |
| 其他（图片/语音等） | 回复「暂不支持该消息类型」或静默 |

**被动回复长度**：文本 ≤ 2048 字节；超长截断并附 H5 链接。

### 5.6 菜单与关注提示

- 后台编辑器将按钮树校验为微信允许的结构：一级 3 个以内、二级每个一级 5 个以内；`view` 必须有 `https` URL（或站内相对路径，发布时拼站点域名），`click` 必须有唯一 `key`。
- 「发布」= `menu/create`，成功后写 `menu.publishedAt`；「拉取当前菜单」= `menu/get`，回填草稿（覆盖前提示）。
- 关注欢迎语、关键词回复、默认回复保存在配置里，由被动回复实时读取，保存即生效（无需发布）。
- 关键词匹配按「精确 → 包含 → 默认」顺序；同一关键词多条时取排序靠前且启用的。

### 5.7 定时任务

| 任务 | 频率 | 作用 |
|---|---|---|
| 推送重试 | 每分钟 | 扫描 `failed` 且到期的记录 |
| 场景清理 | 每小时 | 删除过期 1 天以上的 `wechat_mp_bind_scenes` |
| 记录清理 | 每天 | 推送记录保留 180 天，入站事件保留 30 天 |
| 到期提醒 | 每 5 分钟 | 扫描任务到期/审批超时，调用 `pushByEvent`（P2） |

定时任务放在现有调度框架内，单实例执行；多实例时用数据库抢占（`status=pending` 的条件更新）避免重复。

|---|---|
| `/m/inbox` | 消息收件箱：未读/全部、按分类筛选，卡片展示标题、摘要、时间；点击进详情 |
| `/m/inbox/[id]` | 消息详情：正文、关联单号、操作按钮；已读自动上报 |
| `/m/task/[id]` | 任务详情与快捷处理（P2：接任务/完成/驳回） |
| `/m/approval/[id]` | 审批详情与同意/驳回（P2，复用 OA 审批接口） |
| `/m/service/[id]` | 客服工单回复（P2） |

**登录与免登录**

- 默认复用现有会话 Cookie；未登录跳 `/login?next=<当前H5地址>`，登录后按 `safeNextPath` 回跳。
- P2 可选「微信网页授权免登录」：在微信内打开时走 `snsapi_base` 静默授权拿 `openId` → 查绑定 → 签发会话；`state` 一次性随机值防 CSRF，授权码 5 分钟内使用，未绑定则回登录页，不自动注册。需在公众号后台配置「网页授权域名」。

**链接映射**

- 推送里的 URL 不直接复用桌面端链接（桌面路由在手机上体验差），由 `mobileLinks` 配置 + 事件键映射到 `/m/*`。
- 无法映射的桌面链接：H5 详情页展示摘要与「在电脑端处理」提示，避免死链。

**样式**

- 移动端单列、底部安全区适配；沿用现有全局样式与 `Panel` 体系，不引入新的 UI 框架。

## 八、安全、合规与风控

| 风险 | 措施 |
|---|---|
| 伪造回调 | 强制校验 `signature` / `msg_signature`，时间戳偏差 > 5 分钟拒绝；使用常量时间比较 |
| 密文配置泄露 | AppSecret / EncodingAESKey 使用 AES-256-GCM（`EXTERNAL_CRED_KEY` 派生上下文密钥），接口只返回是否已配置；日志不打印明文 |
| 二维码被转发冒绑 | 场景值绑定固定 `userId` + 5 分钟 TTL + 一次性使用；绑定只接受当前登录用户创建的场景 |
| 一号多绑 / 多号互抢 | `openId` 唯一；绑定前检查 `userId` 与 `openId` 双向冲突，冲突时拒绝并提示先解绑 |
| 回调重放 | `MsgId` 唯一键幂等；事件哈希兜底；重复请求直接成功不重复处理 |
| 回调超时 | 同步只做验签/解密/被动回复，其余异步；5 秒内必回 |
| 消息轰炸 | 日上限、免打扰时段、去重窗口、仅事件驱动；不做营销群发 |
| 开放跳转 | 模板 URL/菜单 URL 只允许站内相对路径或 HTTPS 白名单域名；前端跳转统一走 `safeNextPath` 类校验 |
| XSS | 菜单名称、模板变量、通知标题渲染前转义；H5 不使用 `dangerouslySetInnerHTML` 渲染用户内容 |
| 接口滥用 | `bind-scene` 按用户限频；后台接口仅 `PLATFORM_ADMIN`；回调按 IP 与总速率限流 |
| 敏感数据 | 日志中 `openId` 脱敏（前 6 后 4）；绑定列表仅管理员可见；导出不含 openId 全量 |
| 审计 | 配置保存、菜单发布、管理员解绑、单条重试均写 `auditLogs` |
| 合规 | 首次关注回复中说明消息用途与退订方式（回复「退订」可关闭推送或解绑）；不发送与用户无关的营销内容；遵守微信模板消息运营规范 |

**「退订」处理**：用户回复「退订/取消」→ 置 `pushMuted=true`（保留绑定，可再次回复「订阅」恢复），被动回复确认；避免用户只能去微信里取关。

## 九、管理员准备材料（上线前在公众号后台完成）

1. **账号类型**：已认证的微信服务号（订阅号不支持模板消息/客服接口的完整能力）。
2. **开发者配置**：
   - AppID、AppSecret（后台填写，AppSecret 只显示一次）。
   - 获取 access_token 的服务器出口 IP 加入 **IP 白名单**（生产、预发分别配置）。
   - 服务器配置 URL：`https://<站点域名>/api/public/wechat-mp/callback`。
   - Token：与后台填写一致（3-32 位）。
   - EncodingAESKey：43 位随机字符串，与后台一致。
   - 消息加解密方式：推荐**安全模式**。
3. **模板**：在「模板库」选用所需模板（任务提醒、审批提醒、客服回复等），记录 `template_id` 与字段名，回填后台模板映射。
4. **菜单**：可先在后台编辑发布，也可先拉取现有菜单再改。
5. **网页授权域名 / 业务域名**：H5 需要网页授权免登录时配置（P2）；普通 H5 跳转只需域名可访问。
6. **自动回复冲突**：服务器配置启用后，公众号后台的「自动回复」可能与被动回复冲突；建议关闭同类自动回复，由本系统统一处理。
7. **隐私与合规**：更新隐私政策，说明收集 openId、昵称、头像用于消息触达；提供解绑与退订入口。
8. **HTTPS 与网络**：回调必须 HTTPS、公网可达、无反代缓冲；证书有效。

## 十二、风险与开放决策

### 12.1 模板消息能力变化

微信对模板消息的运营规范持续收紧，若账号只能使用「订阅通知」，P1 需增加「一次性订阅通知」适配层：用户每次授权一次、发一条。数据模型与推送记录已按 `kind` 预留，无需改表。

### 12.2 单服务号 vs 多服务号

本期只支持平台级一个服务号，`wechat_mp_bindings` 的 `userId` 唯一即体现这一约束。未来要多服务号时，增加 `accountKey` 维度并调整唯一键即可；配置也需从单键改为按账号分键。

### 12.3 与现有「AI 客服」公众号的关系

`agent-assistant.channel.ts` 已有公众号接入，用于企业自备公众号的 AI 客服。若平台服务号与该渠道是**同一个公众号**，微信只允许一个服务器 URL，需要统一回调入口按 `ToUserName`（原始 ID）或 AppID 分发；本期默认两者使用不同公众号，若冲突则在 P2 做分发器，不改变本方案的数据模型。

### 12.4 多实例部署

access_token 缓存与异步队列在单实例内最简单。多实例时：token 可改为数据库/Redis 共享缓存；异步处理依赖 `MsgId` 幂等，重复执行安全；定时任务用数据库条件更新抢占。若当前为单实例部署，P0 不做分布式协调。

### 12.5 回调 5 秒与被动回复

关注欢迎语、关键词回复必须同步返回，若数据库或微信接口抖动可能超时。处理策略：被动回复只读内存配置 + 简单查询，不调用外部接口；绑定写入失败时仍返回兜底欢迎语，绑定结果由用户点「已关注？刷新」兜底。

### 12.6 用户预期管理

微信推送不是必达。产品文案统一为「关注服务号可接收提醒」，不要写「一定收到」；H5 与站内消息始终是可用的兜底路径。取关、免打扰、日上限、模板审核失败都可能导致未送达，后台推送记录需能解释原因。

## 十三、落地顺序建议

1. 先落 P0 的数据表、配置与回调验签，确保能在真实公众号上完成「关注 → 绑定」。
2. 再接一个事件（建议 `task.assigned`）打通模板消息 → H5 的完整链路，验证模板字段与 URL。
3. 链路稳定后批量接入其余事件，最后补菜单、关键词回复与 H5 操作页。
4. 每批完成后按第十一节对应条目验收，再进入下一批。
