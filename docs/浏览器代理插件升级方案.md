## 一、目标与范围

把现有的**单插件 `extensions/aipdd-enterprise`** 从「按业务下发任务的执行器（分发 / 获客 / 本地 Chrome 指令执行）」升级为 **rtrvr.ai 式的「浏览器代理（Browser Agent）」**：用户在插件侧边栏用自然语言描述要的结果，插件里的 Agent 自主规划、逐步操作浏览器并把结果结构化带回。

必须满足的四件事（逐条对应你的原话）：

| # | 你的要求 | 本方案落点 |
|---|---|---|
| 1 | 结合现有 Chrome 插件服务架构，升级为 rtrvr.ai 模式；**基于本系统的模型配置** | Agent 的模型走本系统「模型服务 → 模型广场 / 模型设置」的 ek_ Key + OpenAI 兼容网关，不引入第三方付费模型（§四、§七） |
| 2 | 插件前端页面**布局完全参考 rtrvr.ai**，**样式与本系统一致** | 侧边栏（side panel）复刻 rtrvr 的分区布局；颜色/圆角/字号全部映射到本系统设计令牌（§五） |
| 3 | RPA 自动化**第一个菜单＝「设置本地RPA状态」**（显示插件心跳等是否与本账号连接） | 现「本地 Chrome」页签升级为第一个页签「设置本地RPA状态」（§六） |
| 4 | 第二个菜单 **RPA 任务 → RPA 矩阵任务**；后面的 **RPA 账号 / RPA 脚本** 等都可被本插件 Agent 调用；Agent 还可调用**用户在平台配置的技能** | 页签改名 + 能力开放 + 工具网关（§六、§七） |

**不做**（明确划出，避免范围失控）：不新建第二个扩展（沿用「单插件升级」规则）；不做 rtrvr 的广告位 / Google Sheets·Calendar OAuth / WhatsApp / 云浏览器（cloud browser）/ Rover 嵌入 / 套餐付费墙（本站积分与时长卡口径已足够）。

## 二、rtrvr.ai 模式拆解（调研结论）

拆包 `38.3.12_0.zip` + 站点资料后的关键事实（用于对齐，不作为照搬清单）：

**产品形态**
- Chrome 扩展 = **侧边栏 Agent**（`side_panel`），主界面是「聊天式」的：一个输入框 + 「Describe the outcome」，Agent 在已登录的站点上自主操作。
- 三档核心能力：**Act（操作）/ Crawl（爬取）/ Extract（抽取）**；对外的「Act on this site」叫 **A2W**（agent-to-web）。
- 另有：云浏览器、API、MCP（浏览器即 MCP 客户端，也能对外当 MCP 服务器）、**Rover**（可嵌入的 Agent）。

**扩展内部信息架构（从 bundle 的语义化类名还原）**
- 顶栏：`model-dd-*` 模型下拉（含 BYOK、free mode、China routing、effort 档）、`credits-*` 额度条、`settings-*`/`account-panel-*` 账号与设置。
- 主区：`message-*` 消息流（含 `message-credits`、`message-actions`、`message-metadata`）、`code-plan-*`（代码/计划控制台、`code-plan-console-*` 逐行执行日志）、`planner-questions-*`（Agent 反问澄清）、`run-rating-*`（运行评分）。
- 底部 Composer：`composer-utility-bar`、`recording-*`（录制中控制）、`mode-dropdown`（模式切换）、`attach-button`、`Enhance Prompt`。
- 抽屉 / 面板：`chat-library-panel`（会话历史 + 搜索）、`scheduler-*`（计划任务）、`trigger`/`Recent triggers`（触发器）、`skill*`（技能库 + 搜索）、`shortcut*`（快捷方式）、`recording-*`（录制 → 生成工具）、`mcp-*`（MCP 服务器 connect/list/api）、`provider-*` + `model-dd-byok-*`（自带 Key）、`sheet-access-manager`（表格授权）、`onboarding-*`（新手引导）、`ads-consent-*` + `free-mode-*`（免费模式与广告同意）。
- 底部 `footer-bar`：图标按钮 + 计数徽标（历史/任务/技能等）。

**两个关键概念（值得学，但落点要改）**
- **Skills 技能**：分两类——*personal skills*（个人的偏好 / 常驻指令 / 工作流，Agent 学到长期有用的东西就写进去，是 markdown，可读可编辑）；*shared website skills*（关于「怎么操作某个网站」的站点知识，成功运行会让它变更好）。有 Skills Library。
- **Schedules / Triggers / Shortcuts / Recordings**：定时跑、事件触发跑、一次录制复用、录制自动生成「工具」。

**计费**：Free Mode（内置模型 + 每日额度 + 广告）、Credits（API/MCP 调用）、付费解锁更多计划/触发/cookie 同步等；支持自带 Key（BYOK：OpenAI / Anthropic / Gemini / OpenRouter / 本地 Ollama 等）。

```

│  ┌─────────────────────── 侧边栏 Side Panel（新主界面）───────────────┐ │

│  Agent 决策循环（插件侧）—— 规划 → 选工具 → 执行 → 观测 → 再规划        │
│    ├─ 浏览器动作：本机执行（动态注入 rpa-executor.js，闭集动作）        │
│    ├─ 平台工具：调本系统网关（RPA 账号 / 脚本 / 矩阵任务 / 工作流 / 技能）│
│    └─ 模型调用：调本系统模型网关（ek_ Key，模型广场/模型设置口径）        │

                 │ 心跳 / 指令 / 回执（rc_ 令牌，既有设备通道）
                 ▼
┌────────────────────────── 平台侧（本系统后端）─────────────────────────┐
│  设备与会话台账（RpaChromeDevice/Session/Step）· 指令队列                │
│  能力网关：工具目录(契约派生) · 工作流 wf__ · 营销技能库 · Skill 包      │
│  模型网关：模型广场 + ek_ 鉴权 + 计量（时长卡优先，再扣积分）            │
```

**决策 D1（Agent 决策放哪）**：rtrvr 把 Agent 循环放在插件里（扩展直连模型）。本方案采用 **hybrid**——**编排在插件（贴页面、延迟低、离线可降级为「只执行确定性脚本」），模型与工具在平台**（复用模型广场的 Key/计量/时长卡、复用授权闸与工具目录、跨设备一致）。这样既拿到 rtrvr 的交互形态，又不脱离本系统的计费与治理。

## 五、插件前端 UI 复刻（布局参考 rtrvr，样式对齐本系统）

### 5.1 主界面从 popup 迁到 side panel

- 新增 `side_panel`（`chrome.sidePanel`），把现在挤在 popup 里的内容搬进来；**popup 精简**为：登录态 + 一键「打开侧边栏」+ 状态灯 + 「停止所有控制」。快捷键默认 `Alt+A`（避开 rtrvr 的 Alt+R，避免与已装扩展冲突）。
- 窄屏 / 未开侧边栏时回落到 popup 轻界面（只读状态 + 打开侧边栏）。

### 5.2 侧边栏布局分区（照 rtrvr 的骨架）

```
┌───────────────────────────────────────────────────────────────┐
│ [Logo] 设备名 ·  ●在线     [模型▾]  [积分/时长卡]  [⋯ 账号/设置] │  Header
├───────────────────────────────────────────────────────────────┤
│  会话流（可滚动）                                              │
│   ├ 用户：<目标>                                               │
│   ├ Agent 思考卡（可折叠）                                     │
│   ├ 动作卡：点击「搜索」→ ✔ 已执行（缩略截图）                 │
│   ├ 工具卡：调用 chrome.session_start ✔ / 营销技能「..."》 ✔    │
│   └ 结果卡：结构化结果（表格/JSON）+「导出到多维表格」          │  Main
├───────────────────────────────────────────────────────────────┤
│ [模式▾ Act·Crawl·Extract] [附件] 输入目标…        [增强] [发送]│  Composer
├───────────────────────────────────────────────────────────────┤
│ [历史] [技能] [计划] [触发器] [录制] [MCP] [模型]      (2)      │  Footer
└───────────────────────────────────────────────────────────────┘
        ↑ 每个 Footer 图标打开右侧 Drawer（叠在 Main 上）
```

- **Header**：设备名（对应 clientId 的 `name`）、连接状态灯（灰/绿/黄/红）、模型下拉（数据来自本系统模型广场，含「本账号默认模型」）、积分/时长卡条（读本系统额度）、账号菜单（登录 / 退出 / 更新）。
- **Main**：消息流。卡片类型固定：思考 / 动作 / 工具 / 结果 / 截图 / 错误 / 追问。动作卡与工具卡都能展开看参数与原始回执。
- **Composer**：单行目标输入 + 「模式」切换（三点一横的 `Segmented`，**不是** antd Tabs）、附件（图片/文件 → 数字资产）、发送。**「增强提示」**按钮把一句话扩写成更清晰的目标（走本系统模型）。
- **Footer**：图标按钮 + 计数徽标，打开 Drawer：会话历史（搜索）、技能库（搜索/分类）、计划任务、触发器、录制、MCP 服务器、模型与 Key。

### 5.3 样式对齐（rtrvr 类名 → 本系统令牌）

| rtrvr 分区 | 本系统落点 |
|---|---|
| 颜色 / 背景 / 边框 | `--ant-color-bg-container`、`--ant-color-border-secondary`、`--ant-color-primary`（已在 `frontend/src/app/globals.css` 定义） |
| 圆角 / 阴影 | `--radius-card` 与既有卡片阴影口径 |
| 字号层级 | 与 `/help` 正文一致（正文 14、次要 12、标题 16） |
| 布局组件 | 复用既有 `Panel` / `PanelTabs` / `TabStrip` 的视觉规范（**页签用折行胶囊，不用 antd Segmented 做页签**） |
| 状态色 | 沿用 `PHASE_COLORS` 一套（绿=在线 / 红=离线 / 黄=等待确认 / 灰=未登录），全站同色 |
| 深浅色 | 跟随本系统布局设置（导航主题），不单独做主题 |

> 一句话：**结构照 rtrvr，皮肤用本系统**。插件内所有颜色/圆角/间距都从本系统令牌取，禁止出现 rtrvr 的原生样式。

### 5.4 明确「不照搬」

广告位、Google 登录 / Sheets / Calendar / Drive 授权、云浏览器、WhatsApp 任务、Rover 嵌入、Free-Mode 设备锁、套餐升级墙。这些在本系统用**积分 + 时长卡**替代。

## 六、RPA 自动化菜单改造

### 6.1 页签顺序与命名（`frontend/src/app/rpa/page.tsx`）

| 序 | 现名 | 新名 | 内容 |

| 1 | 本地 Chrome | **设置本地RPA状态** | 本账号的插件连接自检：设备在线灯、心跳时间、扩展版本、当前会话、待确认队列、「停止所有控制」；含「新建互动任务 / 矩阵任务」入口 |
| 2 | RPA 任务 | **RPA 矩阵任务** | 见 6.2 |

| 4 | RPA 脚本 | 不变 | Automa JSON / JS / Python / **chrome_actions 动作序列**；开放给插件 Agent |
| 5 | 设置 | 不变（或并入第 1 个页签的折叠区） | 比特浏览器实例配置、LLM 默认模型（D5 待确认是否并入页签 1） |

深链沿用 `?tab=`；`chrome` 键改为 `status`，旧 `?tab=chrome` 做 301 兼容映射。

### 6.2 「RPA 矩阵任务」的定义（**待你确认，见 §十一 决策 N1**）

三种候选，推荐 **A**：

- **A（推荐）· 任务 × 设备矩阵**：一张表，行 = 任务（脚本/技能 + 账号 + 参数），列 = 在线设备 / 账号维度，可勾选「一个任务下发到 N 台设备并行跑」，并在一屏里看每格的进度、结果与回放入口。适合「同一套操作在多个浏览器/账号上同时干」。
- **B · 任务矩阵视图**：仍是单任务列表，只加一个「矩阵视图」（行=任务，列=状态/设备/进度/结果），本质是任务列表的可视化，不改调度语义。
- **C · 目标矩阵**：行 = 目标站点/平台，列 = 动作，交叉点勾选即生成任务（如「小红书×私信、抖音×私信」）。

> N1 未定前，第二个页签先按「A 的骨架」设计但**不实现批量并行**，只做既有任务列表 + 矩阵视图外壳。

## 七、插件 Agent 可调用的平台能力（工具网关）

插件 Agent 需要「浏览器动作 + 平台工具」两类工具。浏览器动作已就绪；平台工具**不逐个手写**，统一走**契约派生的工具目录**（与站内 Agent / MCP 同源），只补一层「插件侧可调用」的开关与凭据。

| 工具组 | 来源 | 契合约 | 授权 |
|---|---|---|---|
| 浏览器动作 | `rpa-executor.js` | `RC_ACTIONS` | 闭集；敏感动作人工确认 |
| RPA 账号 | `RpaAccount` | `Rpa_accounts` 等 | 只回「密文 → 一次性明文」给本人设备（沿用 D3-A 口径：**默认不下发**，需显式勾选） |
| RPA 脚本 | `RpaScript`（含 `chrome_actions`） | `Rpa_scripts` 等 | 读；回放走设备通道 |
| RPA 矩阵任务 | `RpaTask` | `Rpa_tasks` 等 | 写动作默认不放行（grant） |
| 工作流 | `wf__<id>` | 契约工作流工具 | 授权闸 |
| 营销技能库 | 技能库运行 | `mkt-skills` 相关 | 授权闸 |
| Skill 包 / 插件 | `skillhub` / `agent-skills` | 契约 | 授权闸 |
| 帮助知识库 | `Help_*` | 只读 | 默认开放 |

**关于「用户在平台配置的技能」**：即营销技能库里的技能与用户自己的 Skill 包 / 插件 / 工作流。插件 Agent 通过平台工具网关调用它们，**鉴权用该用户的 `ek_` Key + 该用户的授权闸设置**，不越权、不跨账号。

**「Agent 语义层」工具（已登记为 MCP 专用工具）**：浏览器侧会话已有一组；本方案补一层供**外部 MCP 客户端**用同一套浏览器代理 ——
`browser_agent_start` / `browser_agent_status` / `browser_agent_result` / `browser_agent_stop`、`browser_extract`（抽取成结构化）、`browser_skill_list` / `browser_skill_run`（调技能）。

落地口径（`packages/contracts/src/chrome-rpa.ts` 的 `browserMcpToolArgs` / `browserMcpTools`，并入 `mcpToolArgs` / `MCP_TOOLS`）：
- 走**专用业务字段**（`client_id` / `goal` / `mode` / `session_id` / `skill`），不套通用 `read_data` / `write_data`；
- **绿灯闸**：只有设备 `ONLINE` 才派任务。`client_id` 不给时，本人只有一台在线设备就直接用，多台则列出设备要求指定（不替用户猜）；指定了离线设备如实拒绝；
- **无人值守闸**：MCP 侧发起 / 抽取 / 运行技能 / 停止都按写动作处理（`unattendedDenialOf`）——**MCP 不提供「定时自动发起」**；要让浏览器定时跑，走插件侧「计划任务」（独立链路：调度器直接进会话引擎，执行前先过**绿灯闸**，设备离线当轮跳过）。
- 实现收口在 `backend/src/rpa/browser-agent-tools.service.ts`（只做「语义 → 既有服务」的翻译），会话本体仍是 `ChromeAgentService`：与界面同一个 handler、同一份校验、同一条留痕；
- 站内 Agent 侧不再重复一套：对话/副驾继续用 `chrome_*` 业务工具（`BUSINESS_TOOLS`），两条入口最终落到同一个会话引擎。
