### 2.2 缺口（本次要补的）

1. **前端登录页是「硬编码」的**：`frontend/src/app/login/page.tsx` 里注册只有「用户名 + 邮箱 + 邮箱验证码」一条路径，**不读取** `/api/auth/account-config`；登录只有「账号+密码」。
2. **没有验证码登录入口**：后端 `VerifyScene` 已含 `LOGIN`，但**没有**「发登录验证码 / 用验证码登录」的路由与服务方法。
3. **没有微信扫码**：`Account` 表无 `openid/unionid` 字段；无微信配置；无授权/回调路由。前端有一处 OIDC 机制（`backend/src/mechanisms/mechanism-oidc.service.ts`），但那是**企业级 SSO 身份源**（面向组织成员登录，`/api/public/oidc/:code/start`），**不是**面向 C 端用户的微信扫码，不能直接套用。
4. **后台没有「账号与登录」设置页**：后端 `PUT /enterprise/admin/account/settings` 已就绪，但前端 `frontend/src/app/admin/_components/settings-tab.tsx` 的四个子页签（OSS / AIPDD 平台 Key / 平台级参数 / 站点设置）里**没有**它。
5. **登录方式无开关**：目前只按「注册方式」控制注册，登录方式（常规/邮箱码/手机码/微信）没有独立的开关位。

## 三、数据与配置模型

### 3.1 Prisma（新增，均向后兼容、可空）

拟新增一张**独立绑定表**，不往 `Account` 上加列（更干净、便于以后接多公众号/小程序）：

```prisma
/// 第三方登录绑定（微信等）；一个账号可绑多个来源，来源内 openid 唯一
model AccountBinding {
  id         Int      @id @default(autoincrement())
  userId     String   @db.VarChar(64)
  /// WECHAT_OPEN（网站应用扫码）/ WECHAT_MP（服务号授权）/ WECHAT_MINI（小程序）……
  provider   String   @db.VarChar(24)
  /// 应用维度唯一：同一 provider 下按 openid 找账号
  openId     String   @db.VarChar(64)
  /// 跨应用统一身份（开放平台下同一用户）
  unionId    String?  @db.VarChar(64)
  nickname   String?  @db.VarChar(64)
  avatarUrl  String?  @db.VarChar(512)
  createdAt  DateTime @default(now()) @map("created_at")

  @@unique([provider, openId])
  @@index([userId])
  @@index([provider, unionId])
  @@map("account_bindings")
}
```

> 若你希望**极简**（只接一个微信来源），也可以退化为在 `Account` 上加 `wechatOpenId` / `wechatUnionId` 两列 + 唯一索引。**建议**用独立表（多应用、可扩展、`Account` 不臃肿）。

### 3.2 系统配置键（`system_settings`，与现有 `account_*` 同构）

| 键 | 内容 | 备注 |
|---|---|---|
| `account_register_modes` | 现有：注册方式数组 | 复用 |
| `account_smtp` | 现有：SMTP | 复用 |
| `account_sms` | 现有：阿里云短信 | 复用 |
| **`account_login_methods`** | 新增：登录方式数组 `PASSWORD / EMAIL_CODE / SMS_CODE / WECHAT` | 默认 `[PASSWORD]`，开箱即用无外部依赖 |
| **`account_wechat`** | 新增：`{ provider, appId, appSecretCipher, enabled, scopes, autoRegister }` | Secret AES-GCM 密文，只回掩码；与 SMTP/短信同一套 `AccountCrypto` |

### 3.3 契约（`packages/contracts`）

- 扩展 `/api/auth/account-config` 响应：加 `loginMethods: string[]`、`wechat: { enabled }`（**只回「开没开」，绝不回 AppID/Secret**）。
- 新增操作：`Account_loginByCode`（验证码登录）、`Account_sendLoginCode`、`Account_wechatAuthorize`（取扫码地址）、`Account_wechatCallback`、`Account_wechatBind`。
- 后台 `PUT/GET /enterprise/admin/account/settings` 请求体加 `loginMethods`、`wechat`。

## 四、后端设计（逐条）

### 4.1 登录方式开关（对应需求 3、5）

- `AccountSettingsService` 增 `loginMethods()` / `saveLoginMethods()`，与 `registerModes()` 完全同构（白名单 + 去重 + 通道可用性校验）。
- 放开的约束与现状一致：**开「邮箱验证码登录」前必须先配 SMTP；开「手机验证码登录」前必须先配短信**；开「微信登录」前必须先配微信参数。否则保存时直接报错并给出提示（沿用 `saveRegisterModes` 的文案风格）。
- `/api/auth/account-config` 一并返回 `loginMethods` 与各通道可用性，供登录页动态渲染。

### 4.2 验证码登录（对应需求 3）

- 新增 `AccountService.sendLoginCode(channel, target)`：校验「该登录方式已开 + 通道已配 + **该邮箱/手机已存在账号**（避免给未注册目标发码，防枚举可只回统一文案）」，复用 `NotifyChannelService.sendEmailCode/sendSmsCode(scene='LOGIN')`。
- 新增 `AccountService.loginByCode(channel, target, code, ctx)`：`consumeCode('LOGIN', ...)` → 按 `email/phone` 找账号 → 校验封禁 → 签会话（`remember` 同样生效）→ 写登录审计。
- 新增路由：`POST /api/auth/local/login-code`（发码）与 `POST /api/auth/local/login-by-code`（登录）；沿用 `session.ts` 的 `RateWindow` 限流（账号 + 来源两道）。

### 4.3 注册验证方式选择（对应需求 2）

- 后端**已经**支持 `mode=USERNAME|EMAIL|PHONE`（`register()` 与 `/api/auth/local/register` 均在）。
- 本次只需：前端注册页**读 `account-config` 动态渲染** —— 只开邮箱就只显示邮箱验证；只开手机就只显示手机验证；都开则给「邮箱/手机」二选一（用项目统一的胶囊切换控件）。
- 可选增强（需你定，见决策点 D5）：注册时**强制**「邮箱或手机至少验证其一」，未验证不允许注册。

### 4.4 微信扫码登录 + 扫码注册（对应需求 1）

**接入方式三选一（见决策点 D1）**，推荐 **A：微信开放平台「网站应用」扫码**（`https://open.weixin.qq.com/connect/qrconnect`）：

流程：
1. 登录页「微信扫码」→ 后端 `GET /api/auth/local/wechat/authorize` 生成**一次性 state**（随机串 + 时间戳，签名后存校验表或短 TTL），返回 `qrconnect` 授权 URL（带 `appid/redirect_uri/scope=snsapi_login/state`）。
2. 用户扫码授权 → 微信回跳 `redirect_uri?code=...&state=...`。
3. 后端回调 `GET /api/auth/local/wechat/callback`：**校验 state**（一次性、防 CSRF）→ 用 `code` 调 `sns/oauth2/access_token` 换 `access_token + openid`，再调 `sns/userinfo` 取 `unionid` 与昵称头像（可选）→ 按 `unionId`（优先）或 `openId` 找 `AccountBinding`：
   - **已绑定** → 直接签会话、写 Cookie、跳回 `next`（可带 `remember`）。
   - **未绑定且开了自动注册** → 走注册：生成用户名（如 `wx_<openid 后 8 位>`）、写 `Account` + `AccountBinding`，赠分/邀请码逻辑复用 `register()` 尾部。
   - **未绑定且未开自动注册** → 跳「绑定已有账号」页：用「账号+密码」或「邮箱/手机验证码」证明身份后把绑定写到当前账号。
4. 全程写 `AuditLog`（`ACCOUNT_WECHAT_LOGIN` / `ACCOUNT_WECHAT_BIND`）。

**安全要点（必做）**：
- `state` 一次性 + 短有效期；回调 `redirect_uri` 必须与后台配置/站点域名严格一致（对齐现有站点域名三级优先级：后台站点设置 ＞ `SITE_URL` ＞ 访客当前地址）。
- AppSecret 只存密文；前端与 `account-config` **永不回传**。
- 微信侧 `errcode` 全量处理；失败不落库、不建账号。
- 绑定唯一性冲突（同一个人两个微信号绑同账号等）给明确文案。

> 备选 **B：服务号「网页授权」`snsapi_userinfo`**——需要已认证服务号 + 配置「网页授权域名」，扫码体验依赖公众号生态；
> 备选 **C：小程序码**——需要小程序主体，通常给 App/小程序用，不是网页登录首选。

### 4.5 记住密码（对应需求 4）

- **现状已实现「30 天内自动登录」**（`remember=true` → 令牌 TTL 30 天，勾选框已在登录页）。
- 需补齐的是口径澄清与两个小项：
  1. 勾选后写入会话（服务端），**不落明文密码**——这是安全底线，浏览器「记住密码」的自动填充由 `input autocomplete` 交给浏览器密码管理器，前端已设 `current-password`，无需后端额外存密码；
  2. 可在登录页保留「账号名」预填（本地存储用户名，不含密码），提升免输体验。
- 若你要的是**「记住账号名+密码自动填充」**的更强语义，则属前端行为增强（不涉后端存储），可在同一批一起做（见决策点 D4）。

### 4.6 后台配置接口（对应需求 5）

- 在现有 `PUT /enterprise/admin/account/settings` 上扩展 `loginMethods` 与 `wechat` 两个可选块（保持「不传即不动」的语义）。
- `maskedView()` 增加 `loginMethods`、`wechat:{ provider, appId, configured, enabled, autoRegister }`（Secret 只回 `••••••`/空）。
- 复用 `AccountCrypto` 加密微信 Secret。

## 六、安全与风控清单（实现时逐条自检）

- [ ] 验证码：只存哈希、5 分钟有效、60 秒重发、单目标日上限、连错 5 次作废（**现有能力，直接复用**）。
- [ ] 限流：发码与验码都按「账号 + 来源 IP」两道（复用 `session.ts` 的 `RateWindow`）；登录连错锁定沿用现状。

- [ ] 绑定唯一性：`(provider, openId)` 唯一索引；一个账号绑多渠道、一个渠道绑一账号的冲突文案明确。
- [ ] 审计：登录成功/失败、微信绑定/解绑、后台改配置全部写 `AuditLog`。
- [ ] 敏感配置：SMTP 密码 / 短信 Secret / 微信 Secret 一律 AES-GCM（`AccountCrypto`），后台只回掩码。

## 十二、补充：注册协议与隐私政策（2026-11-11）

**目标**：注册前必须勾选认可《用户注册协议》与《隐私政策》，点击链接可看全文；平台管理员在后台可编辑正文，改完即时生效。

### 12.1 协议文本

| 编码 | 标题 | 分类 | 全文页 |
|---|---|---|---|
| `USER_REGISTRATION` | 用户注册协议 | REGISTRATION | `/agreement/register` |
| `USER_PRIVACY` | 隐私政策 | PRIVACY | `/agreement/privacy` |

平台内置标准文本在 `backend/src/account/agreements.default.ts`（注册协议 10 条、隐私政策 8 条，含第三方共享/委托处理）。
后台尚未发布时，注册页勾选与全文页都用这份默认文本（版本 `v1.0`），保证开箱状态即可注册。

### 12.2 公开读取

- `GET /api/public/terms/:code`：返回当前生效版本全文；未发布时回落默认文本并标 `source: "DEFAULT"`，已发布为 `"CUSTOM"`。
- `GET /api/public/terms/register-consents`：注册前必读清单（编码 / 标题 / 当前版本 / 正文），登录页据此渲染勾选项与版本号。
  （该路由必须声明在 `:code` 之前，否则会被参数路由抢先匹配。）

### 12.3 服务端强制与留痕

- `POST /api/auth/local/register` 与遗留 `POST /api/auth/register` 接受 `terms: [{ code, version }]`；
  `TermsService.requireRegisterConsent` 按「当前生效版本」逐项比对，缺项或版本过期直接 400「请先阅读并同意《…》」，
  且校验发生在消耗验证码、占用用户名之前，用户勾选后可原样重试。
- 同意校验通过后建号，并在同一步写 `TermsAcceptance`（编码 / 版本 / 时间 / IP / 浏览器标识）；
  留痕写入失败只记 `ACCOUNT_AGREEMENT_RECORD_FAILED` 审计，不回滚已建账号（版本强校验已成立，补的是凭证）。
- 微信「自动注册」同受约束：扫码前的勾选状态随一次性 `state` 传递（`terms=CODE@VER,...`），未同意则不建号并提示回注册页勾选。

### 12.4 后台维护

「系统设置 → 账号与登录 → 注册协议与隐私政策」：显示两份协议当前状态（已发布版本 / 平台默认文本），
「编辑并发布」弹出版本号（自动 +0.1）、标题与全文编辑器；保存即以新版本发布为 ACTIVE，同编码旧版本自动归档，
接受旧版本的用户留痕保留。复用既有 `/enterprise/terms/documents` 与「条款版本」台账页。

### 12.5 验收

- 不勾选 → 前端拦截；绕过前端直接调接口 → 400 且不建号、不消耗验证码。
- 版本不符（后台刚发布新版）→ 400，提示重新确认协议。
- 勾选并注册成功 → `terms_acceptance` 出现两条记录，带版本、时间、IP、UA。
- 后台发布新版本 → 登录页勾选链接立即指向新正文，旧版本归档。
